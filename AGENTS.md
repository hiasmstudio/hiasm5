# Инструкции для агентов в репозитории HiAsm

Этот файл читают помощники для кода (Claude Code, Codex и другие) перед работой. Все команды и пути проверены в этом репозитории. Если что-то расходится с кодом, верьте коду и поправьте этот файл.

## О проекте

- HiAsm — IDE визуального программирования: схема (`.sha`) собирается из элементов. GUI на GTK4 и gtkmm 4, язык C++17.
- Пакеты лежат в `packs/<имя>`:
  - `cpp` — «Приложение на C++»; основной пакет, который развивается;
  - `_base` — Core: элементы `hc*`, шаблоны, примеры;
  - `web`, `modules` — переносы пакетов HiAsm 4 на C++;
  - `_hiasm4` — `paths.ini` со списком установок HiAsm 4.
- Установка HiAsm 4 (`C:\Program Files (x86)\HiAsm`, Delphi) открывается только для чтения. Это источник переноса и данных для тестов. Ничего в ней не менять.

## Сборка и тесты (Windows, MSYS2 UCRT64)

- Перед сборкой и перед `ctest` выполните `export PATH=/c/msys64/ucrt64/bin:$PATH`. Без этого g++ и тесты падают без сообщения.
- Конфигурация и сборка: `cmake --preset windows-mingw-gtk4-debug`, затем `cmake --build --preset windows-mingw-gtk4-debug`. Каталог сборки: `build/Windows_MinGW-x64-GTK4-Debug`.
- Один тест собирается целью `<имя>_test`: `cmake --build build/Windows_MinGW-x64-GTK4-Debug --target form_editor_test -j 8`.
- Запуск одного теста: `cd build/Windows_MinGW-x64-GTK4-Debug && ctest -R "^form_editor$" -V`.
- Полный набор: `ctest --timeout 500 -j 2`. Занимает около 6,5 минут, в основном из-за `cpp_hc`. Команды длиннее двух минут запускайте в фоне.
  При `-j 2` наблюдались ложные сбои: таймаут `main_docks` и падение `cpp_hc` с «database is locked» на общей базе `int/hiasm.db`. Для проверки используйте последовательный запуск `ctest --timeout 900` (около 9 минут): он проходит, кроме `win32_ime` без патча.
- Известные исключения:
  - `win32_ime` падает с кодом 0xC0000409, если не собран патченный рантайм GTK4 в `build/deps/gtk4-win32` (скрипт `tools/build_gtk4_runtime.ps1`);
  - `rtcg` пропускается (код 77) только если пакет `cpp` не зарегистрирован. При установленном пакете тест запускается (около 80 с) и проходит.
- Python: команда `python3` из Windows PATH — заглушка Store, она печатает `Python` и выходит с кодом 49. Используйте `/c/msys64/ucrt64/bin/python3` после выставления PATH.
- Визуальную проверку агент не может выполнить сам. Тесты, которые снимают окно (GSK или PrintWindow), дают картинку для оценки. Если окно не смотрели, так и пишите в отчёте.

## Карта репозитория

- `src/` — ядро и GUI: `SDK` и `Element*` (схема и элементы), `Elements.cpp` (`createElement`), `FormEditor.cpp` (встроенный редактор форм), `LegacyFormEditor.cpp` (окно формы HiAsm 4), `WindowManager.cpp`, `DockWorkspace.cpp`, `PropEditor.cpp`, `Pack.cpp`, `LegacyPackCatalog.cpp`, `RTCG/` (генератор кода).
- `tests/` — тесты ctest. Регистрация в `CMakeLists.txt`, функция `add_test`.
- `packs/cpp/`:
  - `conf/<Имя>.ini` — конфиг элемента (свойства, точки, класс);
  - `code/<Имя>.hws` — шаблон RTCG, генерирует C++ (старое имя `hi<Имя>.hws` тоже читается);
  - `icon/<Имя>.ico` — иконка;
  - `lang/ru/conf/<Имя>.lang` — русские подписи;
  - `example/` — учебные схемы, `new/` — шаблоны новых проектов;
  - `elements.sql` — источник базы элементов (`groups`, `elements`, `planned_elements`).
- `packs/_base/` — Core: `conf/hc*.ini`, иконки `.png`, `elements.sql`. Код для `hc*` лежит в `packs/cpp/code/hihc*.hws`.
- `resources/` — `hiasm.sql` (команды, параметры, строки интерфейса), `lang/`, иконки приложения.
- `MARKDOWN/` — рабочие документы на русском.
  - Сгенерированные, не править руками: `DELPHI_MIGRATION.md` и `.json` (`tools/audit_delphi_migration.py`), `CPP_ELEMENTS_PLAN.md` (`tools/cpp_elements_plan.py`).
  - `CHECKLIST.md` — журнал работ. Это не доказательство: каждое утверждение подтверждается тестом.
  - Правила переноса элементов из Delphi: `MARKDOWN/DELPHI2CPP_ELEMENTS_RULES.md`.
- `tools/` — генераторы, сборка и упаковка.
- `cmake/StageRuntime.cmake` — копирует `packs/` в каталог сборки и пересобирает `elements.db` из `elements.sql` (только в каталоге сборки).

## Правила работы

- Язык: общение и документы на русском. Строки интерфейса пишутся через `ui_tr("…")`, перевод добавляется в `src/Localization.cpp`.
- Это не git-репозиторий. Не создавать коммиты, ветки, `stash`, `reset` без прямой просьбы. Пока работа не готова, не удалять файлы.
- Не править: `build/`, сгенерированные файлы, установку HiAsm 4.
- Перед удалением или перезаписью файла посмотреть его содержимое.
- Изменения пакетов проверять тестами: палитра (`cpp_package`), кодогенерация (`cpp_hc`, `cpp_widgets`, `cpp_entries`), схемы и шаблоны (`new_project`, `form_editor`, `rtcg`).
- Номера `info_id` 9000xx общие для `packs/cpp/cpp_package.sql`, `resources/hiasm.sql` и `src/MainDataBase.cpp` (`INSERT OR IGNORE`). Перед выбором номера искать его во всех трёх местах: совпадение молча оставляет один текст.
- Кодировки в `packs/cpp`: конфиги сохранены в основном с CRLF (794 из 809) и с UTF-8 BOM (797 из 809), `lang/*.lang` — с CRLF (793 из 794). Новые файлы делать по образцу соседних.

## Ловушки, которые уже встречались

- RTCG: `include` — служебное слово; тернарный оператор с `==` внутри присваивания не разбирается, пишите `if`; `d('Имя')` снимает данные из потока при каждом вызове, читайте его в переменную один раз.
- Скрытая панель не имеет родителя в дереве виджетов. Тест `main_docks` ждёт шесть панелей на старте. Не прятать панели внутри `DockWorkspace`, чтобы «починить» тест.
- GTK4: `GtkScrollbar` не является `GtkRange`, работайте через его `adjustment`.
- Win32-код оборачивается в `#ifdef _WIN32`; на Linux остаётся явный no-op с комментарием.
- Схемы хранят значения свойств по имени, а комбобоксы — числовым индексом. Переименование свойства или перестановка списка ломает сохранённые схемы.
- Коды пакетов HiAsm 4: `pack->name` в приложении всегда в нижнем регистре (`pda`, `pocketpc`), а `packs.codename` в `Int/hiasm.db` записан как есть (`PDA`, `PocketPC`). Сравнивать без учёта регистра (`lower()`), иначе компилятор пакета не находится.

## Перенос элементов Delphi → C++

Порядок и правила описаны в `MARKDOWN/DELPHI2CPP_ELEMENTS_RULES.md`. Кратко: конфиг сохраняется по именам и типам Delphi, код переписывается на RTCG, элемент попадает в палитру только после `elements.sql` и прохождения `cpp_package`.
